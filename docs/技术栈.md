# 技术栈与技术选型

## 技术栈一览

- **语言**: Java 17
- **构建工具**: Maven
- **数据库**: SQLite (默认) + 可扩展到 MySQL/PostgreSQL/MongoDB
- **向量数据库**: 支持本地向量存储 + 外部向量数据库（如 Chroma、Pinecone）
- **AI 服务**: Dashscope (阿里云通义千问)
- **嵌入模型**: 支持多种嵌入模型（Dashscope Embedding、OpenAI Embedding 等）
- **界面**: CLI (命令行) + Web（与会话能力、流式输出能力对齐）
- **流式与异步编排**: **Project Reactor**（`reactor-core`），流式对话与 SSE 侧统一为 `Flux`/`Mono`；测试使用 `reactor-test`（`StepVerifier`）
- **可观测与运维**: 结构化日志、可选 OpenTelemetry（请求与 Tool 调用关联 trace id）

以下为**既定或推荐**的技术选择，实现时须与 [产品能力规格](产品规格.md)、[架构说明](架构.md) 一致；若需偏离，须在评审中说明并更新本文档。

## 响应式与流式对话：Project Reactor

| 选型                     | 说明                                                                                                                                                                                                                            |
| ---------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **核心库**                | **Project Reactor**（`io.projectreactor:reactor-core`）。流式 LLM 输出、流式 RAG 生成、可取消的长时间对话链路**统一**用 Reactor 建模，避免各层各自用回调/线程拼凑。                                                                                                       |
| **流式类型约定** | **`Flux<T>`**：按时间到达的 token 片段、流式事件（如 `ChatChunk`）、SSE 推送序列等。**`Mono<T>`**：单次异步结果（如非流式补全、一次 Tool 调用结果、单次 DB 写入）。具体领域类型名在代码中统一即可。 |
| **AIProvider** | 流式返回 **`Flux<StreamingChunk>`**：`TextToken` 带 **`ModelOutputKind`**（如 `THINKING` 思考链、`FINAL` 正文，对应 Dashscope `reasoning_content` / `content`）；另有 `ToolCallsFinished`；**业务编排**（`AgentEngine` / `application`）不直接依赖阻塞式 `InputStream` 轮询。 |
| **Web（SSE）** | 与 **Reactor** 对齐：在 **Spring WebFlux** 下可将 `Flux` 直接映射为 **SSE**（`ServerSentEvent`）；若使用 Servlet 栈，控制器仍应返回 **`Flux`** 或 `SseEmitter` 并由上游订阅同一 `Flux`，**禁止**在 `application` 层写两套互不等价的流式逻辑。 |
| **CLI** | 订阅 `Flux`：`doOnNext` 写终端；测试或脚本场景可用 `blockLast()`，**生产 CLI 路径**宜保留背压与取消（用户中断）。 |
| **阻塞 IO 与 Reactor 混用** | SQLite / JDBC 等**阻塞** API 必须放在 **`Schedulers.boundedElastic()`** 上执行（如 `Mono.fromCallable(() -> …).subscribeOn(Schedulers.boundedElastic())`），**禁止**在 `parallel` 等默认用于 Reactor 链的线程上直接阻塞。后续若引入 **R2DBC** 可再评估全链路非阻塞，本文档不强制首版。 |
| **测试** | 对 `Flux` / `Mono` 使用 **`reactor-test`** 的 **`StepVerifier`** 做确定性断言（含完成、错误、取消）。 |

## Web 与依赖注入（推荐）

| 选型         | 说明                                                                                                                                                                |
| ---------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Web 框架** | 推荐 **Spring Boot 3 + WebFlux**，与 Reactor 同属一套生态，便于 SSE、路由过滤器与全局异常到 `Flux` 错误信号的统一处理。若团队坚持使用 Servlet，则须在文档中固定「MVC + `Flux` 返回 SSE」的写法，避免阻塞式 `RestTemplate` 混入流式路径。 |
| **依赖注入**   | Spring **或** 轻量容器均可；**要点**是 `ChatApplicationService`、`AgentEngine` 等**单例**依赖会话作用域对象时，通过工厂或显式传参注入「当前会话上下文」，避免在 Reactor 链外持有可变会话状态。                                 |

## 其它

| 领域             | 推荐                                                                       |
| -------------- | ------------------------------------------------------------------------ |
| **CLI 行编辑与历史** | **JLine** 3.x（与 `System.in` 解耦、支持历史与补全）                                  |
| **JSON**       | **Jackson** 2.x（与 Spring 默认一致）或项目统一一种                                    |
| **配置**         | **YAML**（`application.yml`）+ 类型安全的 `@ConfigurationProperties`（若用 Spring） |

## Maven 与依赖版本

| 项 | 说明 |
|----|------|
| **当前阶段** | 单模块 `pom.xml` 显式声明 **SLF4J API**、**Jackson**、**Logback**、**Reactor**、**sqlite-jdbc** 等；**`exec-maven-plugin`** 默认主类 `com.sophon.Sophon`；**`maven-dependency-plugin`** 在 `package` 时将依赖复制到 `target/lib/`，与 **`maven-jar-plugin` 清单 Class-Path** 配合，可用 `java -jar target/sophon-*.jar` 运行（见 [开发与运行 — 常用命令](开发与运行.md#toc-common-commands)）。 |
| **引入 Spring Boot 后** | 使用 **`spring-boot-dependencies` BOM** 时，**Reactor** 版本一般由 **BOM 统一管理**；应**删除或注释**与 BOM 冲突的显式 `reactor-core` 版本号，避免版本漂移。 |
| **Web 相关依赖** | `spring-boot-starter-webflux` 等与「Web 与依赖注入」章节同时引入；具体坐标以 `pom.xml` 为准。 |
| **多模块演进** | 当需要 **CLI / Web / 核心库独立发版**或被其他项目依赖时，再拆为多模块；**alpha 阶段保持单模块即可**。 |
