## 安全与远程访问（拓展预留）

**当前默认（本地 / 局域网）**：通过 **Token** 与 **IP 白名单**（如仅 `127.0.0.1`）控制访问，满足个人或可信局域网场景。

**以下能力不作为首版必做，作为架构拓展点预留**，在需要公网或不可信网络访问时再迭代：

- **传输安全**：TLS 终止、证书管理、HSTS 等
- **凭据生命周期**：Token 签发与**轮换**、撤销与过期策略
- **细粒度权限**：针对 **Plugin**（JVM 内）与 **MCP**（进程外）分别定义能力边界，例如读文件路径范围、是否允许执行系统命令、出站网络与敏感 API 访问等
- **与统一能力注册联动**：工具/资源在注册时声明所需权限，运行时校验

首版实现可只覆盖本地模型；文档与配置结构中可为上述项保留占位（例如 `server.yaml` 中的 `tls:`、`auth.rotation:` 等），避免后续大改接口。

## 配置管理

### 配置文件结构
```
~/.sophon/
├── config/
│   ├── server.yaml              # 服务端配置
│   ├── llm.yaml                 # LLM 配置
│   ├── cache.yaml               # 缓存配置
│   └── agents/                  # Agent 配置目录
│       ├── coding_agent.yaml    # 代码分析 Agent
│       ├── review_agent.yaml    # 代码审查 Agent
│       └── test_agent.yaml      # 测试 Agent
├── sessions/
│   └── {session_id}/           # 会话配置
│       └── config.yaml
├── plugins/                     # 插件目录
├── logs/                        # 日志目录
└── data/
    ├── cache/
    ├── database/
    └── server.pid              # 服务端进程 ID
```
（可选）在 `config/secrets/` 下存放仅本机可读密钥文件，权限 `0600`，勿提交版本库。

### 密钥与敏感配置

- **与代码路径分离**：业务源码与安装目录中**仅**放非敏感默认值与示例；API Key、长期 Token、数据库口令等**不得**与可提交仓库路径混放，避免误提交。
- **读取优先级（建议）**：**环境变量**（如 `DASHSCOPE_API_KEY`、`SOPHON_TOKEN`）优先 → 操作系统**密钥链** / 仅用户可读的密钥文件 → 仅在 `${SOPHON_HOME}/config/` 下的受控文件（如 `secrets.local.yaml`，**必须**列入 `.gitignore`）。
- **避免明文长期落盘**：高价值密钥尽量不落盘；若必须文件存储，限制文件权限、备份范围，并文档化轮换方式（与「安全与远程访问」拓展一致）。

### 服务端配置 (server.yaml)
```yaml
server:
  host: "127.0.0.1"
  port: 8080
  protocol: "http"                # http 或 grpc
  max_connections: 100
  timeout: 30000
  # Request Gate（背压，可选；见 docs/架构设计.md「背压与请求门控」）
  # gate:
  #   max_concurrent_requests: 64
  #   max_concurrent_per_session: 4

authentication:
  enabled: true
  token: "${SOPHON_TOKEN}"
  allowed_clients:
    - "127.0.0.1"
  # 以下为远程/加固场景预留（首版可忽略）
  # rotation:
  #   enabled: false
  #   token_ttl: 24h

# 以下为远程访问预留（首版可忽略；与 HTTP 并存时由反向代理或内置实现二选一）
# tls:
#   enabled: false
#   keystore_path: ""
#   keystore_password: ""

llm:
  default_provider: "dashscope"
  providers:
    dashscope:
      api_key: ${DASHSCOPE_API_KEY}
      base_url: https://dashscope.aliyuncs.com/api/v1
      model: qwen-max
      timeout: 30000
    openai:
      api_key: ${OPENAI_API_KEY}
      base_url: https://api.openai.com/v1
      model: gpt-4
      timeout: 30000
    claude:
      api_key: ${ANTHROPIC_API_KEY}
      base_url: https://api.anthropic.com
      model: claude-3-5-sonnet-20241022
      timeout: 30000

cache:
  max_size: 1000
  expire_after_write: 10m
  expire_after_access: 5m

storage:
  type: "sqlite"
  path: "${SOPHON_HOME}/data/database/agent.db"

logging:
  level: INFO
  file: "${SOPHON_HOME}/data/logs/server.log"
  max_size: 100MB
  max_history: 10

a2a:
  enabled: true
  default_collaboration_mode: "taskflow"  # master, peer, taskflow, voting
  message_timeout: 30000
  max_retries: 3
  max_concurrent_agents: 10
```

### Agent 配置示例 (coding_agent.yaml)
```yaml
agent:
  id: "coding_agent"
  name: "代码分析专家"
  role: "code_analyzer"
  description: "专注于代码分析、重构和优化的 AI Agent"

llm:
  provider: "dashscope"
  model: "qwen-max"
  temperature: 0.7
  max_tokens: 4000

tools:
  enabled:
    - code_analyzer
    - file_reader
    - git_operations
  disabled: []

skills:
  enabled:
    - code_review
    - refactoring
    - performance_optimization
  disabled: []

prompt:
  system_prompt: |
    你是一个代码分析专家，擅长分析、重构和优化代码。
    你可以识别代码中的问题，提供改进建议，并帮助优化性能。
    始终提供清晰、可操作的建议。

collaboration:
  mode: "taskflow"  # master, peer, taskflow, voting
  capabilities:
    - "code_analysis"
    - "code_generation"
    - "code_refactoring"
  dependencies: []  # 依赖的其他 Agent
```

## 数据与持久化

### 迁移策略

- 会话、消息与元数据的 **schema 变更** 使用 **Flyway** 或 **Liquibase** 对 SQLite（及若使用的 H2）做**版本化迁移**，随服务端版本发布执行 `migrate`，避免手工改库导致环境不一致。
- 迁移脚本与代码**同仓、同版本号**；破坏性变更通过多步迁移与兼容期完成，并在 CHANGELOG 中注明。
