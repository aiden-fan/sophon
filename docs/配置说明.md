# 配置说明

与 [架构 — Session 持久化](架构.md#toc-session-persistence)、[会话命令](会话命令.md) 配合阅读。

## 配置覆盖优先级（自高到低）

<a id="toc-config-priority"></a>

1. **环境变量**（含密钥类，如 `DASHSCOPE_API_KEY`）
2. **用户级配置**（若实现，如 `~/.sophon/application.yml`）
3. **项目内** `src/main/resources/application.yml` 及引用的 `mcp.yml` 等
4. **代码内默认值**（仅作最后兜底）

同一键冲突时以上述顺序为准；文档与实现需保持一致，避免「改了 yml 不生效」的困惑。

**与会话配置的关系**：全局 YAML / 环境变量决定**默认**注册与默认启用策略；**每个会话**在数据库中的 `SessionCapabilityConfig` 为**覆盖层**，不改变全局注册表，仅改变「当前会话可见 subset」。`/命令` 与 Web API 只修改会话层。

**与 System 提示的关系**：全局键 `sophon.ai.system-prompt`（及 `SOPHON_SYSTEM_PROMPT`、启动参数 `--system-prompt` / `-s`）提供**默认值**；**每个会话**可有独立的 **system 提示覆盖**（与会话 id 绑定），修改后只影响该会话的后续轮次，直至清除或切换会话。覆盖的**持久化**纳入 `SessionCapabilityConfig`（或与会话同行的等价字段）；详见 [System 提示](#toc-system-prompt)。

<a id="toc-logging"></a>

## 日志级别

| 键 / 环境变量 | 说明 |
|---------------|------|
| `sophon.logging.level` | 应用于 **`com.sophon`** 包（SLF4J + Logback），如 `INFO`、`DEBUG`、`TRACE` |
| `SOPHON_LOGGING_LEVEL` | 环境变量覆盖，优先级高于 YAML（与上文「配置覆盖优先级」一致） |

入口在 `ConfigManager.load()` 合并配置后调用 `LoggingConfigurator`，再输出调试日志；将级别设为 **`DEBUG`** 可查看配置合并路径、SQLite 初始化、会话创建与消息追加等细节。测试默认使用 `src/test/resources/logback-test.xml`，将根级别设为 `WARN` 以减少噪音。

## AI 与 Dashscope

| 键 / 环境变量 | 说明 |
|---------------|------|
| `sophon.ai.api-key` | 可选、仅作兼容或本地调试；**生产与仓库样例请留空**，真实密钥使用环境变量 **`DASHSCOPE_API_KEY`**（运行时优先于本键；`ConfigManager.load()` 也会把该环境变量合并进配置） |

| `sophon.ai.timeout-seconds` | 单次请求超时 |

<a id="toc-system-prompt"></a>

## System 提示与会话绑定（`system-prompt`）

| 层级 | 说明 |
|------|------|
| **全局默认** | `application.yml` 中 `sophon.ai.system-prompt`；可为空字符串表示「不注入 system 消息」（若实现选择「空则跳过 system 行」）。 |
| **环境覆盖** | **`SOPHON_SYSTEM_PROMPT`**：覆盖 YAML（与 [配置覆盖优先级](#toc-config-priority) 一致）。 |
| **进程启动覆盖** | 启动参数 **`--system-prompt <文本>`**、**`-s <文本>`** 或 **`--system-prompt=文本`**：仅**本次 JVM 进程**内覆盖 YAML 与环境变量；用于脚本/CI 一次性指定。 |
| **会话级覆盖（绑定 sessionId）** | **每个会话**可单独设置 system 提示，**仅影响该会话**内后续 `buildMessagesForModel` / 编排；切换会话后使用各会话自己的值。未设置会话覆盖时，沿用全局链（YAML → 环境 → 启动参数）。清除会话覆盖后，回到该全局链。 |
| **生效顺序（从低到高）** | 代码默认 → `application.yml` → `~/.sophon/application.yml` → **`SOPHON_SYSTEM_PROMPT`** → **启动参数** → **会话覆盖**（最高）。 |

**修改方式**

- **CLI**：**`/prompt`** / **`/prompt show`** 查看当前生效文本；**`/prompt set <一行>`** 绑定到**当前会话**；**`/prompt clear`** 清除本会话覆盖。会话级覆盖经 **`ConversationManager`** 写入 **`SessionCapabilityConfig.systemPrompt`** 并落库；与 **`SlashCommandRouter`**、**`SessionCapabilityService`** 统一入口（与 Web 对齐）。命令全集见 [会话命令](会话命令.md)。
- **Web**：`PATCH /sessions/{id}/capabilities`（或等价 DTO 字段 `systemPrompt`）与 CLI **同一语义**，不得另写一套编排。

**持久化约定**：会话级 system 提示属于**会话能力/元数据**，应与 `Session` 或 `SessionCapabilityConfig` **一并读写**；导出/导入会话时**应包含**该字段。

<a id="toc-agent"></a>

## Agent 编排

| 键 | 说明 |
|----|------|
| `sophon.agent.max-rounds` | 单次用户输入内，至多执行几次「模型调用」（含 **tool 跟进**）；仅对话无工具时可改小 |
| `sophon.agent.tools-enabled` | 为 `false` 时不向模型声明 `tools`（与未注册工具时一致） |

编排入口为 `com.sophon.core.agent.AgentEngine`；`ChatApplicationService` 委托其执行。**Tool 注册与多轮调用循环**与阶段 5、6 门禁对齐，见 [交付阶段 — 里程碑要点](交付阶段.md#toc-milestones-1-6) 与 [架构 — 分层职责](架构.md#toc-layering)。

<a id="toc-resilience"></a>

## 失败与重试策略

超时、重试、熔断的**默认值以 `application.yml` 与代码中的 `@ConfigurationProperties`（或等价绑定）为准**；下表为**语义与配置键约定**，落地后须保持**文档、配置样例、代码默认值**三者一致。

| 范围 | 关注点 | 文档约定 |
|------|--------|----------|
| **Agent 整轮** | 多轮「模型 → Tool → 模型」防无限循环 | 配置 **最大轮次**、**整轮总超时**。达到上限须向用户返回可读错误，并写审计（若启用）。 |
| **单次 LLM** | 网络与供应商限流 | **单次调用超时**、对**可重试**错误的 **重试次数与退避**；**不可重试**（4xx 业务错误）不重试。 |
| **单次 Tool（含 MCP）** | 本地执行与远程 stdio | **单次执行超时**；MCP 另需 **连接超时**、**首包/整段响应超时**。 |
| **流式（Reactor）** | 取消与背压 | 客户端断开或用户中断时 **dispose 订阅**，向上游传播取消；**禁止**在已取消的链上继续写业务结果。 |
| **熔断（可选）** | 连续失败保护 | 对同一 Tool、同一 MCP server 或同一模型端点可配置 **滑动窗口失败阈值 + 打开时长**。 |
| **降级** | 主模型不可用 | 与 [产品规格](产品规格.md) 一致：备用模型、仅 RAG、仅规则回复等路径**超时与重试策略单独可配**。 |

**配置键示例**（实现时写入 `application.yml`，下列键名可随项目命名空间微调，但须在文档中同步）：

```yaml
resilience:
  agent:
    max-rounds: 32
    total-timeout: 5m
  ai:
    request-timeout: 120s
    retry:
      max-attempts: 3
      backoff: 500ms
  tool:
    execution-timeout: 60s
  mcp:
    connect-timeout: 30s
    call-timeout: 120s
    retry:
      max-attempts: 2
```

## 主要配置文件与目录

- `application.yml`: 应用主配置（可含 **Profile** 定义：命名快照 → Tool/Skill/KB 组合）
- `skills/`、`skills/builtin/`: Skill 配置与实现
- `tools/local/`、`tools/mcp/`: Tool 与 MCP 配置片段
- `knowledge/`、`knowledge/docs/`、`knowledge/config/`: 知识库资源与样例
- `db/`: 数据库迁移脚本

更细的「资源路径 ↔ Java 包」对应见 [开发与运行 — 项目结构](开发与运行.md#toc-resource-mapping)。

## 环境变量

- `DASHSCOPE_API_KEY`: **Dashscope API 密钥（推荐唯一来源）**；**勿**将密钥写入 `application.yml` 或提交到仓库
- `DASHSCOPE_MODEL`: 默认模型名称（覆盖 `sophon.ai.model`）
- `DATABASE_URL`: 数据库连接 URL
- `STORAGE_TYPE`: 存储类型 (sqlite/mysql/mongodb)
- `SKILL_DIRS`: 技能目录列表 (逗号分隔，默认: builtin,~/.sophon/skills)
- `SKILL_HOTLOAD`: 是否启用技能热加载 (true/false，默认: true)
- `TOOL_DIRS`: 工具配置目录列表 (逗号分隔)
- `MCP_ENABLED`: 是否启用 MCP 工具 (true/false，默认: true)
- `MCP_CONFIG_PATH`: MCP 配置文件路径 (默认: config/mcp.yml)
- `KNOWLEDGE_ENABLED`: 是否启用知识库功能 (true/false，默认: true)
- `KNOWLEDGE_DIR`: 知识库目录 (默认: ~/.sophon/knowledge)
- `EMBEDDING_PROVIDER`: 嵌入向量提供商 (dashscope/openai/huggingface)
- `VECTOR_STORE_TYPE`: 向量存储类型 (local/chroma/pinecone)
