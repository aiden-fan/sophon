- `Anthropic Java SDK`: Claude API 客户端（可选）

## 框架依赖与适用场景

### Reactor（响应式编程）

- **主要使用场景**：
  - LLM 流式输出（token/chunk 持续推送）
  - 多 Agent 协作中的并发任务编排与异步聚合
  - MCP / 外部工具调用的 I/O 密集链路（高并发、非阻塞）
  - 事件驱动模块（如 Event Bus、状态变化通知）
- **收益**：统一异步模型、便于在 **Spring `api.gate`** 与 Web 链路上做背压（**Gate 不进 `core`**）、降低阻塞等待成本。
- **注意事项**：
  - 避免在响应式链路中执行阻塞操作（本地文件大 IO、阻塞 JDBC、长时间 CPU 任务）。
  - 必要时通过独立线程池隔离阻塞段，防止影响核心事件循环。
  - 复杂编排优先放在 `Orchestrator`，避免在 Reactor 链里堆积业务分支导致可读性下降。

### Spring WebFlux / Netty

- **主要使用场景**：服务端 **HTTP 接口层**（Controller、Filter、DTO、SSE/WebSocket 适配）、请求级并发处理；**以及由 Spring 托管的会话/配置/消息持久化**（Repository、`SessionPersistenceService`、事务）与 **薄用例编排**（加载会话 → 调 `core` → 写回）。
- **边界**：**Spring 管「边界与 I/O」**：传输、安全、**DB 读写**、事务；**`core.*` 管「Agent 真相」**：在 **已加载会话快照** 上 **组装 `AgentInstance`、运行 `AgentEngine`、产出待落库增量**（见 [架构设计.md](架构设计.md)「分层：Spring 与领域核心」「用户对话路径」）。
- **会话级绑定配置**：**HTTP + 落库在 Spring**；**绑定校验与 `AgentFactory` 语义在 core**（`SessionAgentBindingService` + `AgentFactory`），避免把领域规则写进 Controller。
- **组合关系**：`Netty` 提供高性能异步网络层，`WebFlux` 提供响应式 Web 抽象。
- **实践建议**：接口层保持薄；领域逻辑避免大量 `@Component` 穿透到 Engine 内部，以免与框架生命周期纠缠。

### gRPC（可选）

- **主要使用场景**：内部高吞吐、低延迟调用；需要强类型接口与流式通信时。
- **适用边界**：对外开放优先 REST/OpenAPI；内部性能敏感链路可补充 gRPC。

### Caffeine

- **主要使用场景**：会话元数据、能力清单、短期上下文片段缓存。
- **实践建议**：与 `Trace`/指标联动，持续观察命中率与过期策略是否合理。

### Flyway / Liquibase

- **主要使用场景**：SQLite/H2 的 schema 演进、版本发布迁移。
- **实践建议**：迁移脚本与代码同版本管理，避免手工改库造成环境漂移。

## 核心特性

### 架构特性
- **客户端-服务端分离**、**多客户端可连服务端**（CLI/Web；**同一会话独占一连接**）、**独立守护进程**、**本地通信优化**
- **编排与 Engine 分离**、**Capability Registry**、**结构化 Trace**、**Request Gate（背压）**：详见 [项目概述与架构能力清单.md](项目概述与架构能力清单.md) 中架构能力清单与 [架构设计.md](架构设计.md)

### Agent 特性
- **多模型支持**: DashScope (通义千问)、OpenAI、Claude、本地 LLM；**会话内可切换模型**，**入参/出参结构差异由 LLM 适配层吸收**；对外 API 使用 **统一消息与流式事件**（含多模态 `parts[]`、SSE 分段类型）
- **能力抽象与组装**: Tool（**含 MCP 适配为统一 Tool/Capability**）、Skill、RAG、A2A 角色、Prompt、多模态等先抽象为**可替换能力单元**，经 **Registry + AgentFactory/Assembler** 组装为 **Agent 实例**，再由 Engine 调度（见 [架构设计.md](架构设计.md)「Agent 实例与能力组装」）
- **Tool/Skill 系统**: 内置及自定义工具、技能编排
- **会话管理**: 多会话并发；**同一 `session_id` 仅允许一个活跃客户端连接**（独占），策略可配置（拒绝/抢占/release）；**本会话 Agent 绑定可配置**（Spring 暴露 API，core 应用变更并再组装 Agent）
- **知识库集成**: 向量检索、RAG 流水线
- **多模态支持**: 文本、图片、文档处理
- **插件系统**: 热插拔、动态加载、依赖隔离

### A2A 特性 (Agent-to-Agent)
- **本地多 Agent**: 支持创建多个不同角色的 Agent
- **Agent 注册与发现**: 自动发现和管理本地 Agent
- **消息路由**: 智能 Agent 间消息路由和传递
- **协作模式**:
  - **主从模式**: 一个主 Agent 控制多个子 Agent
  - **对等模式**: 多个 Agent 平等协作
  - **任务流模式**: 按 DAG 流程执行 Agent 链
  - **投票模式**: 多 Agent 协商决策
- **协作会话**: 基于 `a2a_session_id` 的多 Agent 编排与受控上下文传递（与用户侧 `session_id` 隔离，参见 [架构设计](架构设计.md) 中的「会话与多 Agent 模型」）

### 安全特性
- **Tool 沙箱执行**: 白名单、资源限制
- **本地认证**: 简单的本地认证机制（见 [安全配置与数据持久化.md](安全配置与数据持久化.md) 中「安全与远程访问」）
- **会话隔离**: 多会话数据隔离（含 `session_id` 与 `a2a_session_id` 的隔离策略，见 [架构设计.md](架构设计.md)「会话与多 Agent 模型」）
- **审计日志**: 操作可追溯
