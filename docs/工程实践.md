### 契约优先（Contract-first）

- **REST**：以 **OpenAPI** 描述 HTTP API；服务端实现、客户端 SDK 与 `common` 模块中的领域模型/DTO **同源演进**，避免 `server` 与 `client` 各自为政。
- **聊天与补全**：OpenAPI 中的 **`input.parts[]`、非流式 `output.parts[]`、流式 SSE 事件 schema** 与 **`core.llm.unified`** 及 **`common` DTO** **同源语义**；**DB 消息 JSON** 与之一致；**不包含**各 LLM 厂商专有请求体作为稳定契约（见 [架构设计](架构设计.md)「LLM 客户端抽象与统一消息模型」）。
- **gRPC（若启用）**：`.proto` 与 REST 资源在语义上对齐或有明确映射表，IDL 与领域模型**同步评审、同步发版**。
- **收益**：减少联调漂移，CLI/Web 与 A2A 共用同一套契约生成或校验逻辑（可选）。

### 集成测试矩阵（最低集）

| 场景 | 目的 |
|------|------|
| 单 Agent 对话 | 会话、聊天、上下文基础路径 |
| Tool 调用 | `Capability Registry` → 内置或 Plugin 工具执行全链路 |
| MCP 连接失败与重试 | 模拟 MCP 不可用/超时，验证退避、错误封装与恢复 |
| A2A 两跳任务流 | 至少两个 Agent 顺序协作，编排状态与 **trace** 可核对 |
| 会话内换模 + 多模态 | 同一会话切换 `provider`/`model` 后，**统一 `parts[]` 入参**仍可用；流式仅出现 **统一事件类型**；不适配内容得到明确错误 |
| 流式 `done` 后落库 | SSE 全程结束后 DB 存在 **完整 assistant 消息**；**无**横跨 SSE 的长事务；断线场景符合架构设计「流式响应与持久化策略」 |

上表所列场景作为集成测试与 CI 的**架构基线**；首版可部分以手动/半自动验收，但接口与模块划分应预留自动化挂载点。
