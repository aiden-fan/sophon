## 项目概述

这是一个基于 JDK 17 + Maven 的本地智能 Agent 框架，采用**客户端-服务端分离架构**。服务端负责核心 Agent 逻辑，CLI 等作为独立客户端连接；**多个客户端可同时在线**，但**同一 `session_id` 仅允许一个活跃控制连接**（独占），避免上下文与流式交错。支持**本地多 Agent 协作 (A2A)**。

核心特性：多模型支持、Tool/Skill 系统、知识库集成、会话管理、上下文维护、插件系统、Agent-to-Agent 协作、MCP 协议支持。

### 架构能力清单（设计要点）

以下能力在文档后续章节中有展开；此处作**速览索引**。

| 维度 | 内容 |
|------|------|
| **编排层** | **Orchestrator** 独立于 **Agent Engine**（之上或并列子模块），负责任务分解、**DAG**、**人机确认**节点，避免 Engine 既管对话又管复杂工作流导致膨胀 |
| **分层** | **Spring**：HTTP/gRPC、安全、**会话/配置/消息的持久化与事务**、薄编排（**加载会话 → 调 core → 写回**）；**`core.*`**：**组装 Agent、Engine 推理、Registry/LLM**，**不**直接 JDBC（见 [架构设计](架构设计.md)「分层」「用户对话路径」） |
| **会话 Agent 绑定** | **按 `session_id` 动态增删 Tool、知识库/RAG 范围**：**REST + 落库在 Spring**；**校验与再组装语义在 core**（`SessionAgentBindingService` + `AgentFactory`），见 [架构设计](架构设计.md)「会话级 Agent 绑定配置」 |
| **LLM 统一契约** | **全 Agent 核心 + 持久化** 仅用 **`Unified*`**；**仅**在 **`LLMClient`（各 Provider）** 内做统一 ⇄ 厂商 format；**对外**统一 `parts[]` 与流式事件；**DB 存统一模型 JSON**（`schema_version`）；扩展用 **tagged union**，见 [架构设计](架构设计.md)「LLM 客户端抽象与统一消息模型」 |
| **Agent 组装** | Tool（**含 MCP 适配**）、Skill、RAG、A2A 角色、Prompt、多模态等先**抽象为能力单元**，经 **Registry + AgentFactory** 组装为 **Agent 实例**，由 **Engine** 统一调度 |
| **能力注册** | **Capability Registry**：Tool / Skill / MCP tool / Plugin 在内部抽象为同一套能力，**UI、CLI、A2A** 共用发现（list/describe）与调用（invoke）语义 |
| **会话连接** | 同一 **`session_id` 独占一个活跃客户端连接**；新连策略可配置（拒绝 / 抢占 / 先 release） |
| **可观测** | 除 **Simple Metrics** 外，预留**结构化 Trace**（如 `session_id`、`agent_id`、`tool_call_id`、`a2a_session_id`、各阶段 **latency**、**token**），便于调试 A2A 与 MCP |
| **背压** | **Request Gate**：**仅 Spring `api.gate` Bean**，**不实现在 `core`**；在调用 core 前完成队列/并发/限流；与 **Agent 能力（core）** 模块独立，见 [架构设计](架构设计.md)「背压与请求门控」 |
| **运行时** | **流式落库**：SSE 与长事务解耦；**`done`** 后短事务写 assistant；用户消息可先行提交。**`AgentInstance` 缓存**：按会话 + 绑定/配置摘要，变更失效，见 [架构设计](架构设计.md) 对应小节 |
| **数据** | 会话与消息的 **SQLite**（及可选 **H2**）**schema 版本化迁移**：使用 **Flyway** 或 **Liquibase** |
| **密钥与配置** | `SOPHON_HOME` 下敏感项与**代码/仓库路径分离**；优先**环境变量**、操作系统**密钥链**或受控文件，避免高价值密钥**明文长期落盘** |
| **工程** | **契约优先**：HTTP **OpenAPI** 与（若启用）gRPC **proto** 与**核心领域模型**同步演进，避免 `client`/`server` 模块漂移 |
| **测试** | **集成测试矩阵**（最低集）：单 Agent 对话、Tool 调用、**MCP 连接失败与重试**、**A2A 两跳任务流** |

展开见 [架构设计](架构设计.md)（Orchestrator、Registry、Trace、Gate 等）、[安全、配置与数据持久化](安全配置与数据持久化.md)、[工程实践：契约与测试](工程实践.md)。功能落地顺序见 [开发计划与路线图](开发计划与路线图.md)（统一编号路线）。
