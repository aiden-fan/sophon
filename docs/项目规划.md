# Sophon Novel 项目规划

## 一、项目定位

一个辅助创作网络小说的本地 CLI 应用：
- 管理小说项目（世界观、角色、大纲）
- 与 AI 协作生成章节
- 风格可控、内容全落文件
- 纯终端交互，无 Web 界面

## 二、核心设计原则

### 极简 + 可扩展

1. **LLM 统一抽象层**：所有内部代码只认一种 DTO，OpenAI/Anthropic/Claude 的差异只在 provider 层做一次映射，绝不渗透到业务代码
2. **无上下文，每次从零**：不维护对话上下文/记忆，每次创作都是「选文档 → 读 → 组装 → 生成 → 写」的一次性流程，防止上下文污染
3. **文档组装强扩展**：用户项目可能有很多文件（总大纲、章节大纲、角色卡、世界观、设定集），组装策略要能灵活组合、排序、过滤
4. **清晰的边界**：CLI 只管交互，core 管逻辑和组装，provider 管翻译

## 三、核心工作流

每次创作请求（如 `/write "写第一章"`）的完整流程：

```
用户输入: "写第一章，主角穿越到仙界"
        │
        ▼
┌─────────────────────────────────────┐
│ Step 1: 文档选择（LLM 决策）         │
│                                     │
│ 把项目文件清单（元数据）发给 LLM     │
│ LLM 决定需要加载哪些文档：            │
│   - outline.md（总大纲）             │
│   - outlines/chapter-01.md          │
│   - characters/张三.md              │
│   - world-setting.md                │
└───────────────┬─────────────────────┘
                ▼
┌─────────────────────────────────────┐
│ Step 2: 批量读取（Tool 一次性加载）  │
│                                     │
│ 调用工具一次性读取所有选定文档        │
│ → 得到原始文本列表                   │
└───────────────┬─────────────────────┘
                ▼
┌─────────────────────────────────────┐
│ Step 3: 上下文组装（ContextAssembly）│
│                                     │
│ ContextBuilder 按策略拼接：          │
│ [system prompt] + [世界观] + [角色]  │
│ + [大纲] + [用户指令]                │
│ → 一个完整的 UnifiedChatRequest     │
└───────────────┬─────────────────────┘
                ▼
┌─────────────────────────────────────┐
│ Step 4: 生成（LLM 一次性生成）       │
│                                     │
│ 发给 LLM → 流式输出到终端供预览      │
│ → 得到完整章节内容                   │
└───────────────┬─────────────────────┘
                ▼
┌─────────────────────────────────────┐
│ Step 5: 写入（Tool 写文件）          │
│                                     │
│ WriteChapterTool → chapters/        │
│ chapter-01.md                       │
└─────────────────────────────────────┘
```

**关键点**：这个流程是一次性的，不保留中间状态。下次创作重新走一遍。

## 五、关键模块设计

### 5.1 LLM 统一抽象

**内部统一模型（core/llm/unified/）：**

```java
// 统一消息角色
enum UnifiedRole { SYSTEM, USER, ASSISTANT }

// 统一消息
record UnifiedMessage(UnifiedRole role, String content) { }

// 统一请求（内部只用这个）
record UnifiedChatRequest(
    String model,
    List<UnifiedMessage> messages,
    double temperature,
    int maxTokens,
    List<UnifiedTool> tools      // 工具定义（用于 tool call）
) { }

// 统一响应
record UnifiedChatResponse(
    String content,
    List<ToolCall> toolCalls,    // 工具调用
    Usage usage,
    String finishReason
) { }

record ToolCall(String name, String argsJson) { }

// 统一流式事件
record UnifiedStreamEvent(String delta, boolean done) { }
```

**Provider 接口（core/llm/）：**

```java
interface LLMProvider {
    UnifiedChatResponse complete(UnifiedChatRequest request);
    Flux<UnifiedStreamEvent> stream(UnifiedChatRequest request);
    String providerName();
}
```

**Provider 实现（只在这里做格式转换）：**

```
core/llm/providers/
├── OpenAIProvider.java      // Unified → OpenAI SDK format → Unified
├── AnthropicProvider.java   // Unified → Anthropic SDK format → Unified
└── MockProvider.java        // 开发/测试用
```

**边界规则：除 `providers/*` 外，任何代码不得 import OpenAI/Anthropic SDK 的类。**

### 5.2 工具系统（Tool System）

**核心接口（core/tool/）：**

```java
// 工具定义（统一模型，给 LLM 和内部都用）
record UnifiedTool(
    String name,         // "read_outline"
    String description,  // "读取小说大纲文件"
    String parameters    // JSON Schema 字符串
) { }

// 工具执行接口
interface Tool {
    String name();
    String description();
    String parametersSchema();
    ToolResult execute(Map<String, Object> args);
}

record ToolResult(String content, boolean isError) { }

// 工具注册表
class ToolRegistry {
    void register(Tool tool);
    Tool get(String name);
    List<UnifiedTool> listAll();  // 给 LLM 看的定义列表
}
```

**内置工具（core/tool/builtin/）：**

```
core/tool/builtin/
├── ListDocumentsTool.java      # 列出项目所有文档（元数据，用于 LLM 选择）
├── ReadDocumentsTool.java      # 批量读取多个文档（一次性加载）
├── WriteChapterTool.java       # 写入章节文件
├── ReadChapterTool.java        # 读取指定章节
└── NovelProjectInfoTool.java   # 获取项目元信息
```

设计思路：`ReadDocumentsTool` 是批量读取，一次拿回多个文档内容，避免多次 tool call 的开销。

### 5.3 文档选择（core/selector/）

**DocumentSelector**：把项目文件清单（带简短描述）发给 LLM，让 LLM 根据用户指令决定需要加载哪些文档。

```java
// 文档元数据（轻量，不读内容）
record DocumentMeta(
    String path,        // "characters/张三.md"
    String type,        // "character" / "outline" / "world" / "chapter"
    String title        // "张三"（从文件名或文件头提取）
) { }

// 选择结果
record SelectionResult(
    List<String> paths  // 选定要加载的文件路径
) { }

interface DocumentSelector {
    // 给用户指令，LLM 分析后返回需要加载的文档路径
    SelectionResult select(String userInstruction, List<DocumentMeta> available);
}
```

### 5.4 上下文组装（core/context/）— 强扩展性

这是核心模块。用户项目文件越来越多，组装策略要灵活。

**设计思路**：基于 **Section** 的拼装模式。每个文档类型对应一个 Section 渲染器，多个 Section 按策略拼接。

```java
// 一个上下文片段（对应一个文档或一组同类文档）
record ContextSection(
    String title,       // "角色设定"
    String content,     // 渲染后的文本
    int order           // 排序权重
) { }

// 组装策略接口
interface ContextBuilder {
    // 输入：选定的文档路径 + 文档内容 + 用户指令
    // 输出：完整的 system prompt 或 message 列表
    List<UnifiedMessage> build(
        Map<String, String> documents,  // path → content
        String userInstruction
    );
}

// 默认实现：按类型分组 → 按顺序渲染 → 拼接
class DefaultContextBuilder implements ContextBuilder {
    // 可配置的 section 渲染器注册表
    void registerRenderer(String docType, SectionRenderer renderer);
}

// Section 渲染器（可扩展）
interface SectionRenderer {
    ContextSection render(List<DocumentContent> docs);
}
```

**默认组装顺序**：
```
[system: 你是一个网络小说创作助手]
[世界观设定]（world-setting.md）
[角色设定]（characters/*.md 合并）
[总大纲]（outline.md）
[章节大纲]（outlines/*.md）
[前序章节摘要]（可选，最近 2-3 章）
[用户指令]
```

**扩展方式**：
- 新增文档类型 → 注册一个 `SectionRenderer`
- 修改顺序 → 调整 `order` 值
- 替换策略 → 换 `ContextBuilder` 实现
- 支持模板 → SectionRenderer 内部用模板引擎

### 5.5 创作流程编排（core/pipeline/）

把上面的模块串起来：

```java
interface CreationPipeline {
    // 输入：用户指令 → 输出：生成的章节内容
    ChapterResult create(String userInstruction);
}

class DefaultCreationPipeline implements CreationPipeline {
    private final DocumentSelector selector;
    private final DocumentReader reader;
    private final ContextBuilder contextBuilder;
    private final LLMProvider llm;
    private final ChapterWriter writer;

    ChapterResult create(String userInstruction) {
        // 1. 列出所有可用文档
        List<DocumentMeta> available = listDocuments();

        // 2. LLM 决定加载哪些
        SelectionResult selected = selector.select(userInstruction, available);

        // 3. 批量读取
        Map<String, String> contents = reader.read(selected.paths());

        // 4. 组装上下文
        List<UnifiedMessage> messages = contextBuilder.build(contents, userInstruction);

        // 5. 生成
        String chapterContent = llm.complete(UnifiedChatRequest.builder()
            .messages(messages)
            .build()).content();

        // 6. 写入文件
        String filePath = writer.write(chapterContent);

        return new ChapterResult(chapterContent, filePath);
    }
}
```

### 5.8 项目初始化（core/init/）

`/new "写一本修仙小说，主角叫张三"` → LLM 生成项目骨架，用户在此基础上修改。

```java
interface NovelProjectInitializer {
    // 根据用户描述，用 LLM 生成项目骨架并创建文件
    void initialize(Path targetDir, String description);
}
```

**初始化流程**：
1. 创建目录结构（`characters/`, `chapters/`）
2. 生成 `novel.yaml` 元信息
3. 生成 `world-setting.md`（世界观模板）
4. 生成 `outline.md`（总大纲模板）
5. 生成初始角色文件（如 `characters/主角.md`）
6. 提示用户进入 `/write` 开始创作

模板文件存在 `src/main/resources/templates/` 下，LLM 填充内容。

## 七、实施步骤

### Phase 1: 骨架（最小可运行）
1. `pom.xml` — JLine + 基础依赖
2. 基础包结构 + `SophonApplication.java`
3. `Unified*` DTO 定义
4. `LLMProvider` 接口 + `MockProvider`
5. `Tool` / `ToolRegistry` + 1 个简单 mock 工具
6. CLI REPL：输入 → mock 响应输出
7. 验证：`./sophon` 启动后能对话

### Phase 2: 创作 Pipeline + 项目初始化
1. `NovelProjectPath` — 项目路径解析
2. `NovelProjectInitializer` — 项目初始化：创建目录 + 模板文件
3. 模板文件：`novel.yaml` / `outline.md` / `world-setting.md` / `character.md`
4. `FrontmatterParser` — 解析 YAML frontmatter
5. `ListDocumentsTool` — 列出项目文件
6. `ReadDocumentsTool` — 批量读取文件
7. `WriteChapterTool` — 写入章节
8. `ContextBuilder` — 最简单实现（固定顺序拼接）
9. `DocumentSelector` — 最简单实现（用户手动指定）
10. `CreationPipeline` — 串起来
11. CLI 命令：`/new "写修仙小说"`、`/novel open ~/my-novel`、`/write "写第一章"`

### Phase 3: LLM 文档选择 + 真实 LLM
1. `LlmDocumentSelector` — LLM 分析文件清单，自动选择
2. 加入 OpenAI / Anthropic SDK
3. `OpenAIProvider` + `AnthropicProvider`
4. 真实 tool call + 流式生成
5. 完整流程：用户指令 → LLM 选文档 → 读取 → 组装 → 生成 → 写入

### Phase 4: 上下文组装扩展
1. `SectionRenderer` 注册表机制
2. 按文档类型自动分组渲染
3. 可配置的组装顺序（`.sophon/sections.yaml`）
4. Prompt 模板管理

### Phase 5: 完善与打磨
1. 流式输出到终端（边生成边显示）
2. 章节生成质量调优
3. 错误处理、重试、超时
4. ANSI 彩色输出
