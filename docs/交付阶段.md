# 交付阶段与门禁

与 [产品能力规格](产品规格.md) 配合：**顺序开发、测试门禁、范围控制**。若与阶段表冲突，**以本页阶段表与门禁为准**。

## 原则

1. **顺序开发**：按阶段 **1 → 2 → …** 依次实现；**当前阶段约定的测试全部通过**后再进入下一阶段。
2. **回归**：进入新阶段前，执行**自阶段 1 起至上一阶段**的自动化测试（`mvn test` 或 CI 等价物）。
3. **范围控制**：每阶段只交付该阶段列出的能力；后阶段需求可在接口上**预留**，不得未完成当前门禁就实现后续功能。
4. **测试资产**：核心逻辑需单元测试；依赖 LLM/MCP 时用 **Mock / 可开关集成测试**；集成测试方式须在 [开发与运行](开发与运行.md) 或本仓库说明中可查找。

### 说明

- 若某阶段因依赖（如云 API 不可用）阻塞，可在该阶段内用 **Mock 实现**通过门禁，但须在下一阶段用真实实现补集成测试。
- 规格全文仍为目标集合；未排入前序阶段的能力**不得**提前实现为默认开启的生产路径。

## 里程碑设计要点（原阶段 1–6 文档整合）

以下为历史分阶段设计的**浓缩**，便于理解地基到会话能力的演进；细节以代码与测试为准。

| 阶段 | 要点 |
|------|------|
| **1** | Maven 单模块、Java 17、`Sophon` 入口、`ConfigManager` + `application.yml`、`StorageAdapter` + SQLite、`Session`/`Message` CRUD、SLF4J/Logback；CLI 仅 smoke，主对话循环属阶段 2。 |
| **2** | `AIProvider` 同步调用 Dashscope（OpenAI 兼容 Chat Completions）、`ConversationManager` 消息顺序、`ChatApplicationService`、CLI 读入→模型→打印；密钥优先 `DASHSCOPE_API_KEY`。 |
| **3** | `AgentEngine` 为编排入口，`max-rounds` 防死循环；与 `ChatApplicationService` 对接；Tool 循环在阶段 5 扩展。 |
| **4** | `AIProvider#completeStreaming` 返回 `Flux<StreamingChunk>`；`DashscopeProvider` 解析 SSE、`tool_calls` 分片合并；阻塞 IO 在 `boundedElastic`；CLI 订阅流式输出。 |
| **5** | `ToolRegistry`、`ToolDefinition`、`ToolExecutor`、`LocalTool`；Agent 在声明 tools 时处理 `CompletionResult.ToolCalls` 与 tool 角色消息。 |
| **6** | `SessionCapabilityConfig` 与会话一并持久化（如 `capabilities_json`）；`AgentEngine` 仅暴露本会话允许的 Tool；`ConversationManager.systemPrompt` 走会话配置落库。 |
