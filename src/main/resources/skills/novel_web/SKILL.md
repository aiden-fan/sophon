# 网络小说（模版仿写）

## 调用方式

通过内置技能 **`novel_web`**（`invoke_skill`，`skill_id` 为 `novel_web`）；参数与 **`markdown_doc`** 相同，便于同一套文件读写契约。

## 参数（JSON）

| 字段 | 类型 | 说明 |
|------|------|------|
| `operation` | string | `create`（仅新建）、`write`（覆盖或配合 append）、`append`（追加）、`read` |
| `path` | string | 文件路径；相对路径相对 JVM 工作目录 |
| `content` | string | 写入时的 UTF-8 正文（`read` 不需要） |
| `append` | boolean | 与 `operation:"write"` 联用时为 true 表示追加 |
| `create_parents` | boolean | 为 true 时自动创建父目录 |

**读模版 / 范文**（模版可为 .txt / .md 等）：`{"operation":"read","path":"模版路径"}`  
**写章节**（产出须为纯文本，路径建议 `.txt`）：`{"operation":"write","path":"novel/ch01.txt","content":"…","create_parents":true}`  
**连载追加**：`{"operation":"append","path":"novel/draft.txt","content":"…"}`

## 输出格式（须遵守）

- **文件**：正文写入 **`.txt`**（或与用户约定之纯文本扩展名），内容为 **UTF-8 纯文本**。  
- **禁止**在小说正文中使用 Markdown 或其它标记语法，包括但不限于：`#` 标题、`##`、`**粗体**`、`*斜体*`、`` ` `` 行内代码、`[]()` 链接、`-` / `*` 列表标记、`>` 引用、表格 `|`、分隔线 `---` 等。  
- **章节名、卷名**：用普通文本行表示即可（例如单独一行「第一章 标题」或用户惯用格式），**不要**用 `#` 层级标题。  
- **分段**：仅用换行与空行分段；列表场景若剧情需要枚举，用叙述句写出，不用 `-` 列表语法。  
- 若用户要求「和模版一样的格式」，指叙事与标点习惯对齐；**除非模版本身含标记**，否则仍输出无标记纯文本。

## 模版分析与仿写（模型须执行）

在用户给出模版、样章或「参考文风」时，在落笔前先完成隐式分析，再在正文中**对齐**这些维度（不必向用户逐条复述，除非用户要求）：

1. **叙事与人称**：第一/三人称、全知/限知、是否有内心独白、是否多视角切换。  
2. **时态与语感**：现代网文常见过去时叙述 + 现在时对话，或全书统一时态；保持与模版一致。  
3. **句长与节奏**：短句偏多还是长描写偏多；动作戏与日常戏的比例。  
4. **对话格式**：引号样式、是否独立成段、有无「说/道」类提示语、对话占比。  
5. **段落习惯**：段长、空行、是否用小标题/章首引语（与模版一致）。  
6. **用词与设定**：现代/古风/玄幻等语体；专有名词、称谓、数字与单位风格与模版统一。  
7. **冲突与钩子**：若模版每章末有悬念或反转习惯，新章节尽量延续同类结构强度。

若用户**未**提供文件路径而直接粘贴模版片段，以上分析仍适用；需要持久化时再用 `write`/`append` 写入 `path`。

## 写作约束

- **先对齐、再发挥**：新开章节应在上述维度上与模版「像同一作者」，剧情可以新编，语感须一致。  
- **避免**：突然改变人称、文白混杂（除非模版如此）、现代梗与模版时代感冲突；**禁止**在交付的小说正文中混入 Markdown/HTML 等标记（见上文「输出格式」）。  
- **新建**优先 `operation:"create"`，避免误覆盖既有稿；高危 `write_file` 须符合会话策略（elevated 等）。  
- 单文件过大时拆章或分路径；模版仅作风格参考，**不**逐句抄袭有版权风险的原文。

## 与 markdown_doc 的关系

- **novel_web**：强调「读模版 → 分析风格 → 仿写网文 → **落盘为纯文本 .txt**」；工具层与 `markdown_doc` 相同，但**产物内容**须为无 Markdown 的小说正文。  
- 若用户只需通用 Markdown 文档读写、无网文仿写或需保留 md 语法，可用 `skill_id=markdown_doc`。
